构建一个健壮的 AI 上下文与记忆管理系统，其本质是从“被动输入静态 Prompt”转向“主动构建动态上下文系统”。以下是提炼出的五大核心设计原则，涵盖了设计时需考虑的维度以及对应的落地实现方案：

## 1. 质量原则：最大化信噪比与注意力管理

**考虑方面：**
随着上下文变长，模型容易出现事实性错误、逻辑连贯性减弱，以及“中间迷失（Lost in the Middle）”效应。系统不能无脑堆砌信息，必须确保模型在任何时刻只接触与当前任务最相关的“高浓度”知识。

**实现方案：**

* **压缩重启 (Compaction)：** 当会话逼近 Token 上限时，利用模型对历史记录进行高保真摘要，丢弃原始对话，带着“浓缩摘要”重启新上下文窗口。
* **按需加载 (JIT Context)：** 不一次性注入全量知识或工具。维护外部标识符（文件路径、数据库查询、网页链接），仅在当前步骤需要时才动态拉取对应内容。
* **工具遮蔽 (Tool Masking)：** 通过 Logits 遮蔽隐藏当前任务不需要的工具，按“Agent子流程 -> 沙箱工具 -> 原子函数”分层披露动作空间，避免“工具爆炸”导致模型困惑。

## 2. 架构原则：分层存储与物理外挂

**考虑方面：**
LLM 本身是无状态的，将其所有记忆和状态保留在对话窗口中极不稳定且成本高昂。必须将记忆根据生命周期进行解耦，并与物理环境深度绑定。

**实现方案：**

* **外化记忆 (Externalization)：** 将系统当前的进度、结论和中间态写入本地文件系统（如 `TODO.md`, `NOTES.md`）。上下文窗口仅保留结论和下一步动作，文件系统作为“终极上下文”。
* **多维记忆分层：** 建立结构化的记忆库，严格区分：
* **短期/工作记忆：** 当前会话的滑动窗口。
* **长期记忆库：** 细分为用户 Profile（习惯/设备）、反馈记忆（用户的肯定与纠错）、项目记忆（外部依赖与Why）和经验记忆（工作流模板）。



## 3. 调度原则：边界清晰与异步流转

**考虑方面：**
什么该记住？什么该忘记？记忆如何写入才不会干扰主线任务？记忆如何检索才不会挤占模型的推理空间？

**实现方案：**

* **确立“存与不存”边界：** 必须存的是隐性偏好、用户纠正和项目关键决策（Why）；坚决不存的是代码模式、可直接获取的文件路径或说明文档中已有的静态内容。
* **后台异步写入：** 采用双 Agent 架构。主 Agent 专注执行当前任务；专门的后台 Agent 负责扫描历史对话并写入全局记忆。同时设置互斥机制，主模型已主动记录的，后台不再重复记录。
* **漏斗式检索与微量注入：** 设定读取上限（如仅扫描前30行，最多200个文件），提取标准摘要后，交由 LLM 匹配当前意图，最后限制单次仅注入极少量记忆（如最多 5 条/4000字节），防重防冗余。

## 4. 效能原则：缓存友好与计算压缩

**考虑方面：**
Transformer 自注意力机制的计算复杂度为 $O(n^2)$。未命中 KV Cache 的 Token 成本和延迟极高。系统设计必须迎合底层硬件与推理引擎的缓存机制。

**实现方案：**

* **稳定前缀 (Stable Prefixes)：** 将系统提示词、核心规则、以及高频不变的记忆放置在上下文的最前端，且尽量保持内容和顺序不变，以最大化复用这部分的 KV Cache。
* **追加式更新 (Append-Only)：** 在多轮交互中，尽量通过在尾部追加新信息（结合压缩重启），而不是频繁修改中间内容，避免导致后续的 Cache 失效。

## 5. 安全原则：敏感隔离与用户主控

**考虑方面：**
长期伴随用户的 Agent 会接触大量隐私数据（API密钥、住址、商业机密）。必须防止记忆越权、数据泄露或模型在生成时无意中暴露敏感凭证。

**实现方案：**

* **前置清洗与零留存 (Data Scrubbing)：** 在后台写入长期记忆前，经过隐私清洗漏斗，通过正则或轻量级模型将高危特征脱敏（如 `[API_KEY_REDACTED]`）。临时凭证仅在工作记忆中存留，用完即焚。
* **沙盒隔离与按需提权 (JIT Authorization)：** 敏感记忆采用独立的高强度加密存储。当模型检索命中敏感记忆片段并试图注入时，必须触发审批流，通过 UI 弹窗获取用户的显式确认。
* **透明面板与主动遗忘：** 向用户暴露可观测、可编辑的记忆面板（如 `PROFILE.md`）。支持全局清理指令（如“忘记关于该项目的所有信息”）及基于生命周期（TTL）的过期自动销毁机制。
