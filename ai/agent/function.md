## 原理
> 模型本身不调用任何工具，只是生成调用信息
> 外部系统负责正真调用工具
### 如何训练的？ 新token，tool_call明确的指令
- 监督微调：标注数据训练；什么适合切换函数输出？怎么写调用指令？怎么处理返回？ 都是概率
- 强化学习： 准确性，鲁棒性，有没有调用；
### 外部实现：
- 外部系统，监控llm输出，看到tool_call,提取json，依据协议调用正真的API
- 工具返回结果，包装为Tool response，方便大模型识别
### 为什么失败？
- 模型问题；
- 工具描述问题，参数不对等
### 实现差异
- 指令标记不同
- 工具描述不同

## 问题
- 总是用同一个工具，其他工具不用
- claude code 40多个工具

### 设计原则
- 万能工具prompt：别用我，用其他工具
- 专用工具好处：输出格式控制，TOKEN预算检查等，文件缓存去重等
- 按需发现工具，工具分层： 1. 核心工具-启动加载；2.延迟工具（按需发现）3.Toolsearch 工具搜索引擎； 精确检索、关键词检索
- 工具输出要有预算： 输出大小有上限；完整输出到文档；
- 搜索工具输出有上限；
- 服务端有提示词缓存： 要控制上下文顺序
