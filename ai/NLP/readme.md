## 上下文长度限定
### transfomer为什么需要位置？
- 每个token和其他所有token之间，互相计算一个注意力分数，依据分数做加权求和
- 计算和顺序无关，token顺序打乱，计算结果一样；置换不变性；并行计算导致顺序丢失
- 位置编码就是补充这个信息：每个位置一个位置向量，加到embeding向量上
### 如何生成位置
- 正弦位置编码：（正弦，余弦），不需要训练，绝对位置
- 科学习位置编码：每个位置分配一个随机向量，和模型一起训练，绝对位置
- llm需要的是相对位置，绝对位置受限于长度，且直接作用于embeding
- RoPE：相对位置，作用于Q，K，施加旋转操作；计算token的注意力分数（旋转后的Q和K的点积），只依赖于（m-n）即token的距离；
- ROPE： 每个维度速度不同；多频率编码，同时编码近距离和远距离的信息；高频维度负责局部关系（相邻token的关系），低频维度负责远距离关系
### 4K为什么不能推理128k？
- 位置编码碰到了没见过的维度： 0-4096.超出每建国
- 位置插值：0-4096 间隔变为0.25,则区间扩大4倍，0.25的距离每见过，需要微调；
- YaRN：不同频率插不同的值或者不插值，可疑从4K扩展到128K或更长
### 输入长度和处理长度的差异
- 开头和结尾信息记得住，中间信息遗忘

## 显存估算
- 模型参数
- 优化器： Adamw，每个可训练参数对因：每个可训练参数额外新增12字节：一阶动量4字节、二届动量4字节，参数主副本4字节 :几百MB
- 梯度： 针对可训练参数：50MB
- 激活值： 前向传播过程中每一层的中间结果，保存供反响传播使用；LORA 是大头，开检查点可疑降低；和batch size 关系很大
### LORA： 核心：冻结原是模型权重，训练新增低值适配器
- LORA新增参数很少，可忽略
- 7B 半精度： 7B * 2字节 = 14GB 模型权重
- LORA 参数： 7B * 0.5% = 35MB
- 优化器： 35MB * 12字节 = 400MB
- 梯度存储： 35MB * 2字节 = 70MB
- 激活值： seq = 2048 + 检查点 = 2-4GB
## LORA 原理
- 冻结原是权重，加一个低秩旁路，训练只更新这个旁路
- A举证：负责：找到关键方向，d-r
- B矩阵：负责映射回完整空间，r-d
- r维度: 任务适配的内在维度
- 小矩阵为什么可疑注入新能力？
- - 权重举证是一个函数
  - 修正定向：r维度的输出被改变，其他维度不变，保证了不会灾难性遗忘
  - 低秩约束限制了修改范围，让变化只在低维子空间里
  - 初始参数是0
- 为什么小矩阵是dizhi的？
- - 内在维度：只有几百或几十个，其他参赛调整是冗余的，真正的更新是在一个低维子空间里
  - 微调在数学上本来就是低秩的
- rank 如何选择？ 过大导致过拟合，超过一定程度效果小
  - 简单任务：r = 4-8
  - 复杂任务：r = 16-32，超过64不会有收益
- 加在那一层？
- - Q，V投影
  - 所有线性层：K 输出 FFN ，参数会多

## 思维链
- 计算本质：每生成一个token，计算量是固定的
- 模型的思考深度和输出token数量直接相关
- 用更多的token，换取更多的计算量
- 记忆机制：思维链将中间结果写进上下文，后面的推理可查询；外部化工作记忆，降低单步负荷
- 激活效应：思维链格式激活了预训练的一种模式，倾向于展开过程
- 最大化任务成功，模型自我演化的策略
- 使用边界：简单任务思考容易出错： 引入中间过程，加大了出错的概率
- 长任务，思考能将真正需要的上下文挤出窗口

## 推理
- 瓶颈是：数据搬运，内存墙
- 训练时通过batch，效率较高，算力是瓶颈

### 70B模型举例
- 生成一次token要搬运140GB的参数，每token 140gflop
- H100显存带宽每秒3.35TB,FP16算力，2000Tflops（理论可做上万次）
- 搬运一次要42ms，每秒24个token，利用率不到1%
### 优化
- 量化： 体积压缩，搬运量压缩
- batching：攒batch，一次打包多个用户请求；continuous batch（流水线batch）
- KV cache：生成一个token需要利用之前所有token的中间结果，减少cache大小
- - PageAttention：切成小块，按需分配，减少浪费
  - MQA/GQA： 从模型架构减少KV数量，压缩cache 大小
- 内存优化
- - flash attention: 重新编排计算顺序，利用SRAM（高速缓存），让数据在SRAM里待更久，减少搬运
  - 投机解码：小模型猜测token，大模型一次验证
  - HBM带宽：2TB/s -》 3TB/s

## KV Cache
### 为什么缓存K，V？
- Q * K 点积： 新token的Q，和所有历史token的K的点积
- Softmax权重
- 加权求和V：Softmax权重 和所有历史token的V做求和
- Q只有一个，是当前请求的，K，V是所有历史token，Q不需要缓存
- K，V缓存，缓存历史token的所有KV，防止重新计算
- KV cache 决定能同时服务多少个客户
### 代价是什么？
- 用显存换算力
- 40层，32个头，头维度128,上下文长度4096,fp16存储
- 一个请求的kvcacheda大小：40 * 32* 4096 * 128 * 2（k和v）* 2(字节) = 2.5GB
### 为什么是推理的瓶颈？
- prefill：用户的输入一次性并行处理，生成初始的KV-cache，算力是瓶颈，和输入长度关系很大
- decode： 每一个token需要从缓存读出整个kvcache，和当前Q，做一次注意力计算；计算量小，一个数据和一堆数据做点积；但是搬运数据量很大；内存带宽瓶颈

## temperature 
- 控制输出的随机性，创造力（实际是概率分布）
- 0则确定性（数值精度，也不是100%），1则创造性
- TOPK 在softmax之后选择最高K概率的token
- TOPP：在softmax之后，累积的该概率小于p，负责砍掉低概率尾巴噪声
### 数学对象是什么？
- 决定模型做选择时的概率形状
- 1.logit：维度是词表，每个数字是对因token的分数
- 2.softmax：转换为概率
- 3.从概率里采样：采样就有随机性
- temperature 在1和2之间，logit/temp 对其进行缩放
- temperature 高，概率分布平缓，否则变尖锐（高分）
