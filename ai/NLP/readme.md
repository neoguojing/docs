## 显存估算
- 模型参数
- 优化器： Adamw，每个可训练参数对因：每个可训练参数额外新增12字节：一阶动量4字节、二届动量4字节，参数主副本4字节 :几百MB
- 梯度： 针对可训练参数：50MB
- 激活值： 前向传播过程中每一层的中间结果，保存供反响传播使用；LORA 是大头，开检查点可疑降低；和batch size 关系很大
### LORA： 核心：冻结原是模型权重，训练新增低值适配器
- LORA新增参数很少，可忽略
- 7B 半精度： 7B * 2字节 = 14GB 模型权重
- LORA 参数： 7B * 0.5% = 35MB
- 优化器： 35MB * 12字节 = 400MB
- 梯度存储： 35MB * 2字节 = 70MB
- 激活值： seq = 2048 + 检查点 = 2-4GB

## 思维链
- 计算本质：每生成一个token，计算量是固定的
- 模型的思考深度和输出token数量直接相关
- 用更多的token，换取更多的计算量
- 记忆机制：思维链将中间结果写进上下文，后面的推理可查询；外部化工作记忆，降低单步负荷
- 激活效应：思维链格式激活了预训练的一种模式，倾向于展开过程
- 最大化任务成功，模型自我演化的策略
- 使用边界：简单任务思考容易出错： 引入中间过程，加大了出错的概率
- 长任务，思考能将真正需要的上下文挤出窗口

## 推理
- 瓶颈是：数据搬运，内存墙
- 训练时通过batch，效率较高，算力是瓶颈

### 70B模型举例
- 生成一次token要搬运140GB的参数，每token 140gflop
- H100显存带宽每秒3.35TB,FP16算力，2000Tflops（理论可做上万次）
- 搬运一次要42ms，每秒24个token，利用率不到1%
### 优化
- 量化： 体积压缩，搬运量压缩
- batching：攒batch，一次打包多个用户请求；continuous batch（流水线batch）
- KV cache：生成一个token需要利用之前所有token的中间结果，减少cache大小
- - PageAttention：切成小块，按需分配，减少浪费
  - MQA/GQA： 从模型架构减少KV数量，压缩cache 大小
- 内存优化
- - flash attention: 重新编排计算顺序，利用SRAM（高速缓存），让数据在SRAM里待更久，减少搬运
  - 投机解码：小模型猜测token，大模型一次验证
  - HBM带宽：2TB/s -》 3TB/s
