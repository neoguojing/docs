# 简历项目展示：企业级 OCR 智能识别与编排平台

**项目背景**：面向银行、保险、财务等行业，解决身份证、银行卡、发票及各类非标业务票据的自动化结构录入需求。
**项目定位**：偏向底层 AI 能力编排与业务解耦的 AI 应用工程平台。

### 核心架构与技术亮点
* **分层解耦与插件化架构**：采用“应用层 + IPS/SFD”架构模式，将上层业务流程与底层 AI 模型深度解耦，封装为标准化插件，支持灵活接入与动态扩展。
* **复杂 AI Pipeline 动态编排**：实现多模型串联的流水线处理，全面打通端到端识别链路。各核心节点技术栈如下：
  * **文字检测 (DBNet)**：基于自适应二值化 (Differentiable Binarization) 技术，高效精准定位各种形状和排版的文本区域。
  * **图像对齐 (Heatmap Regression)**：通过预测关键点概率分布热力图提取坐标，计算透视变换矩阵，实现倾斜形变图像的完美矫正。
  * **文字识别 (CRNN)**：结合卷积与循环神经网络，无需字符级切割即可对不定长文本序列进行高效特征提取与序列识别。
  * **字符纠错 (基于规则)**：依托正则表达式、业务字典与校验逻辑，对原始识别结果进行后处理过滤，确保结构化输出符合业务规范。
* **泛化能力设计（模板化识别）**：针对长尾非标票据研发“模板化配置”能力。摒弃传统的“绝对坐标硬裁剪”，首创“全文 OCR 提取 + 关键字段 (Key) 锚定 + 空间拓扑推断”的混合匹配架构，大幅增强抗拉伸与抗平移畸变的鲁棒性。
* **复杂场景处理（多票据混合路由）**：解决单图多票据痛点。设计前置检测分类网络，精准切分各子票据，通过动态路由将不同票据分发至对应的专用 OCR Pipeline 进行并行解析。

### 个人职责与核心贡献
* 主导 OCR 核心识别 Pipeline 的设计与开发，完成全链路 AI 节点的数据流转。
* 负责底层多模态/视觉模型能力的平台化集成与插件化改造。
* 主导业务流程编排引擎的设计，解决复杂/特殊场景（如长文档 PDF、多票据、非标模板）的架构落地。
* 把控整体 AI 平台工程化质量，保障系统在金融业务场景下的高可用与准确率。

# 面试实战题库与高分回答策略

## 一、 核心技术难点与踩坑经验 (Challenges & Pitfalls)

### 1. 多页大体量 PDF 处理：资源消耗大、切割慢、识别慢、中途出错导致全盘失败，如何解决？
* **痛点分析**：以前系统处理 100 页 PDF 时，是一次性读入内存、串行切割、串行识别。只要第 99 页 OOM 报错或网络波动，整个任务直接失败，内存峰值极高，且耗时让人无法忍受。
* **切割优化（IO 与内存控制）**：弃用低效的 PDF 库，采用 `PyMuPDF` 以流式按需读取并转换为图像（控制 DPI 在 300 左右），避免一次性将所有页面吃进内存导致 OOM。
* **编排调度与断点续传（核心架构重构）**：引入 TaskHub 编排器，结合 Celery 和 PostgreSQL 作为任务队列 (Broker) 和状态管理。将大 PDF 拆分为单页（或 5 页一个 Batch）作为独立子任务下发。系统记录每一页的 `Pending/Success/Failed` 状态。如果某页失败，只需重试该页，全部单页任务完成后，再通过 Reducer 归集输出最终的 JSON 结果。彻底解决了“一页报错，整份白跑”的问题。
* **推理加速 (GPU 利用率)**：拆分出的单页任务并发请求推理服务。在底层配置 Triton Inference Server 的动态批处理 (Dynamic Batching) 机制，将并发到达的单页图片在毫秒级内聚合成一个 Batch 送入 GPU，把吞吐量拉满，彻底解决了识别慢的瓶颈。

### 2. 遇到数字识别不准确（如边框和开头数字1混淆），如何解决？
* **检测层优化（向内收缩）**：DBNet 检测出文本框后，在进行 Crop（裁剪）送入 CRNN 前，对文本框边缘进行**向内微调偏移（Inward Offset）**，或者调整 DBNet 的阈值，剥离掉表格边缘的黑线干扰。
* **识别层优化（数据增强）**：在 CRNN 的训练集中，刻意造一批带左/右边框干扰的负样本，以及带边框的数字“1”的正样本，强制模型学习区分“竖线特征”和“数字1特征”。
* **纠错层兜底（规则过滤）**：在校验阶段利用长宽比和业务逻辑。例如，如果是身份证号，长度固定，如果多出一位前导“1”，且该字符的 Bounding Box 极度细长，直接通过规则将其过滤丢弃。

### 3. 模板化识别的核心过程是什么？如何提高准确率？
* **架构升级迭代**：早期使用“绝对坐标映射”，按 X/Y 坐标直接在原图上抠图，但这种方案对扫描件的变形、平移毫无抵抗力。
* **全文匹配与空间拓扑推断**：重构核心链路后，采用全文匹配方案。新图进来，先跑一遍全局 OCR 拿到全部文本和坐标，然后把业务人员在模板里画的框转化为 Key-Value 空间搜索规则。
* **提升鲁棒性**：例如提取“金额”，系统先在全图 OCR 结果里做模糊文本检索找到“合计”（Key）的坐标，然后根据模板记录的空间关系，抓取它右侧 50 像素内的文本块作为 Value。这种方案完全免疫了图像的平移和轻微拉伸问题。仅当 Key 被印章遮挡找不到时，系统才会降级使用传统的“计算透视变换矩阵”进行绝对坐标兜底。

### 4. 多票据 1:N 识别错误的解决方案？
* **痛点**：前置网络漏检（票据靠得太近粘连）或分类错误（发票当成收据），导致动态路由分发到错误的专用 Pipeline。
* **算法层防粘连**：调整前置检测的 NMS (非极大值抑制) 阈值；对容易粘连的票据场景，采用实例分割网络输出多边形 Mask 代替矩形框，精准剥离背景。
* **架构层降级路由**：设计全局置信度机制。当前置分类网络给出的置信度过低，或者票据在专用 Pipeline 的规则校验节点大面积报错时，触发**降级路由 (Fallback)**，将其打入“通用全字段 OCR 链路”进行无差别识别，并自动流入人工复核队列。

## 二、 业务、沟通与客户管理 (Management & Communication)

### 1. 准确率预期管理（客户要求 100% 准确怎么办？）
* **话术与策略**：“金融客户往往期待极高，但从工程角度没有任何模型能绝对做到 100%。我的策略是向客户交付**‘一套系统’**，而不是单纯交付模型。我在平台设计了‘置信度直通率’机制：整个 Pipeline 综合打分 > 95% 且符合正则校验的数据直接放行入库；低于此阈值的数据自动标红，转入‘人工复核工作台 (Human-in-the-loop)’。这不仅帮客户削减了 80% 以上的录入成本，还用系统流程兜底了 100% 的准确率，获得了业务方的极高认可。”

### 2. 跨团队协作（算法模型太重，导致平台响应时间超标如何解决？）
* **话术与策略**：“遇到算法给的模型体量大、推理耗时长的问题时，我不会直接要求算法重训。我会先进行全链路 Profiling，拿耗时瓶颈数据说话。优化是双向的：在算法与运维侧，我推动在 Triton 上开启 TensorRT 模型量化（如 FP16）降低算子耗时；在架构侧，我将 Pipeline 里原本串行的对齐、识别等无强依赖节点改造为并发执行。通过这种基于数据的跨团队协作，最终在不牺牲精度的前提下跑赢了性能指标。”

### 3. 长尾需求应对与系统价值体现（如何打动业务方）
* **话术与策略**：“以前每新增一种长尾非标票据，都需要算法标数据、重训、后端写死代码，周期长达一周，运维成本极高。我主导上线‘模板化配置’后，直接把定义提取规则的能力赋能给了业务端。现在客户的运营人员遇到新票据，只需花 5 分钟在系统前端画几个框、配好字典即可上线跑通。这不仅大幅释放了研发团队的精力，也成为了平台拿单、留客的核心亮点功能。”
