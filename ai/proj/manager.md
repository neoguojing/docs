# 项目/产品开发管理总结

## 1. 我的管理方法

管理的核心链路：**需求 → 方案 → 拆解 → 推进 → 风险 → 交付**

### ① 需求
首先确认：
* **做什么？**
* **为什么做？**
* **验收标准是什么？**

> **核心目标**：把模糊的业务需求转化为明确、可执行的技术需求。

### ② 方案
* **技术方案与任务拆解**：细化到具体的开发任务。
* **明确依赖关系**：梳理各模块或团队间的前置依赖。
* **对高风险点提前 POC**（概念验证）：尽早排除技术盲区。
* **评估人力、时间、资源**：合理规划项目排期。

### ③ 推进
* 按照 **负责人 + 时间节点 + 里程碑** 进行推进。

> **注意**：推进不是简单地每天催进度，而是重点关注**关键路径**和**阻塞项**。

### ④ 风险
重点关注：
* **技术风险**
* **外部依赖**
* **人力资源**
* **需求变更**

> **原则**：风险前置，问题尽量在开发前暴露。

### ⑤ 交付
交付流程：**开发 → 联调 → 测试 → 部署 → 验收**
* 逐阶段确认，最终关注业务结果和客户反馈。

---

## 2. 实际案例分析

**案例场景**：客户临时增加 OCR 功能

**执行链路**：
1. 客户提出需求
2. 确认业务目标和验收标准
3. 评估算法 / 后端 / 部署的整体影响
4. 拆解任务、确定各项负责人
5. **先做算法和性能 POC**（验证可行性）
6. 核心链路跑通
7. 联调测试
8. 上线验收

**突发情况应对**：如果中途发现算法模型延期怎么办？
> 不会简单等待，而是**先确定接口，用 Mock 数据让后端继续开发**，把算法依赖从关键路径中尽可能解耦。

---

## 3. 需求变更怎么办？

**应对策略：先评估，再决策。**

**评估流程**：
`业务价值` ➔ `技术影响` ➔ `工作量 / 时间` ➔ `项目影响` ➔ **决定当前版本 or 下一版本**

> **重点**：不是一味拒绝需求，而是**管理需求的变化**。

---

## 4. 项目延期怎么办？

**应对流程**：
`找原因` ➔ `确认关键路径` ➔ `调整优先级` ➔ `必要时拆分版本` ➔ **保证核心目标**

> **原则**：不要第一反应就是加班。
> **例如**：核心功能必须上线，非核心功能可以放到下一版本（降级或分期交付）。

---

## 5. 面试官高频追问

| 常见问题 | 核心回答策略 |
| :--- | :--- |
| **如何保证项目按时完成？** | 关键路径 + 里程碑 + 风险前置 |
| **产品需求不合理怎么办？** | 先理解业务目标，再提供技术替代方案 |
| **客户频繁改需求怎么办？** | 评估影响 + 优先级 + 版本管理 |
| **研发进度落后怎么办？** | 找阻塞原因，解决问题，必要时调整资源 |
| **技术方案意见不一致？** | 数据/技术依据 → 方案比较 → 做决策 |
| **领导要求一周完成怎么办？**| 明确范围、时间、资源之间的取舍 |
| **项目延期怎么办？** | 找原因 → 调整关键路径 → 分阶段交付 |
| **如何管理跨团队协作？** | 明确目标、负责人、依赖、时间节点 |

---

## 6. 面试最终回答（总结陈词）

“我主要负责技术侧的项目推进，通常从**需求、方案、任务拆解、进度、风险和交付**几个方面进行管理。

在**需求阶段**，我会先明确业务目标和验收标准；在**方案阶段**，识别技术风险，必要时提前做 POC；在**开发阶段**，按照负责人、时间节点和里程碑推进，重点关注关键路径和阻塞项。

如果出现**需求变更或者项目延期**，我会先评估影响，再通过调整优先级、拆分版本等方式保证核心目标的达成。

我理解技术项目管理的核心，不是单纯地追赶进度，而是**提前发现风险、协调资源，最终保证项目的高质量交付**。”
